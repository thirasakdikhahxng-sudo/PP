# Restaurant Booking — Custom Edition 6.0

ระบบจองโต๊ะและจัดการร้านอาหารที่ปรับปรุงจาก v5.1 โดยคงฐานข้อมูล SQLite และ flow เดิม พร้อมหน้าตาใหม่โทน Forest Green / Ivory / Brass

## ความสามารถหลัก
- ลูกค้าสมัคร/เข้าสู่ระบบ ดูร้าน เลือกโต๊ะและช่วงเวลา จองโต๊ะ และชำระผ่าน PromptPay QR / Mobile Banking ตามการตั้งค่าระบบ
- ลูกค้าสั่งอาหารจากรายการจองที่ยืนยันแล้ว และตรวจสอบยอดค้างชำระ
- แอดมินจัดการร้าน โต๊ะ เมนู โปรโมชั่น การจอง การชำระเงิน ลูกค้า รายงาน สต็อก สูตรวัตถุดิบ ค่าใช้จ่าย และครัว
- แอดมินรับชำระค่าจองเป็นเงินสดได้ มีเลขใบเสร็จแยกจากรายการ Gateway และยกเลิก/บันทึกคืนเงินได้
- เพิ่มบัญชีพนักงานและกำหนดสิทธิ์แยก: ดูออเดอร์, จัดการครัว, รับเงินค่าจอง, รับเงินค่าอาหาร
- พนักงานเข้าสู่ระบบด้วยบัญชีที่แอดมินสร้าง แล้วใช้เมนู “พื้นที่พนักงาน”
- นำปุ่มจำลองชำระเงินออกจากหน้าลูกค้า; endpoint จำลองจำกัดเฉพาะแอดมินและใช้ได้เมื่อ PAYMENT_MODE=mock เท่านั้น
- ป้องกันการสร้างรายการชำระค่าอาหาร pending ซ้ำใน booking เดียวกัน

## ติดตั้งบน Windows
1. ติดตั้ง Node.js รุ่น 22.13 ขึ้นไป (แนะนำ LTS รุ่นล่าสุด)
2. แตก ZIP ไปยังโฟลเดอร์ที่ต้องการ (ไฟล์ `package.json` อยู่ที่โฟลเดอร์หลัก ไม่ต้องเข้าโฟลเดอร์ซ้อน)
3. ดับเบิลคลิก `install.bat` หรือเปิด PowerShell ในโฟลเดอร์เดียวกับ `package.json` แล้วรัน `npm install`
4. แก้ `.env` ตามต้องการ; สำหรับฐานข้อมูลเดิมให้ตรวจ/แก้ PromptPay ของแต่ละร้านในแอดมิน > ร้านอาหาร (ค่า `PROMPTPAY_ID` ใน `.env` ใช้ตอนสร้างร้านใหม่ในฐานข้อมูลใหม่)
5. ดับเบิลคลิก `start.bat` หรือรัน `npm start`
6. เปิด `http://localhost:3000`

## บัญชีเริ่มต้น
- อีเมลเริ่มต้น: `admin@example.com`
- รหัสผ่านเริ่มต้น: `admin1234` เฉพาะเมื่อไม่ได้กำหนด `ADMIN_PASSWORD`
- สำหรับฐานข้อมูลใหม่ ระบบจะสร้างบัญชีแอดมินตามค่า `ADMIN_EMAIL` และ `ADMIN_PASSWORD` ที่ตั้งไว้ใน `.env`
- สำหรับฐานข้อมูลใหม่ `ADMIN_PASSWORD` จะถูกใช้ตอนสร้างแอดมินครั้งแรก ห้ามเปิดระบบสู่สาธารณะโดยใช้รหัสผ่านเริ่มต้น

## ตั้งค่า .env
- `PORT=3000`
- `ADMIN_EMAIL=admin@example.com`
- `ADMIN_PASSWORD=ตั้งรหัสผ่านที่คาดเดายาก`
- `PROMPTPAY_ID=หมายเลขพร้อมเพย์ของร้าน`
- `PAYMENT_MODE=mock` สำหรับทดสอบภายใน หรือ `live` เมื่อเชื่อม Gateway และตั้ง `PAYMENT_WEBHOOK_SECRET` แล้ว
- `DATA_DIR=./data` (ค่าเริ่มต้น)

## ข้อมูลและฐานข้อมูล
- Repository นี้ไม่รวมฐานข้อมูล `data/booking.db` เพื่อป้องกันการเผยแพร่ข้อมูลบัญชีและประวัติการจองส่วนตัว เมื่อเริ่มระบบครั้งแรก ระบบจะสร้างฐานข้อมูลใหม่ในโฟลเดอร์ `data` อัตโนมัติ
- เมื่อเริ่มระบบครั้งแรก ตาราง `staff_members`, `booking_cash_receipts` และ `schema_migrations` จะถูกสร้างเพิ่มโดยไม่ลบข้อมูลเดิม
- ก่อนอัปเดตเวอร์ชันให้สำรองทั้งโฟลเดอร์ `data` โดยปิดเซิร์ฟเวอร์ก่อนคัดลอก
- หากลบโฟลเดอร์ `data` ระบบจะสร้างฐานข้อมูลใหม่และข้อมูลตัวอย่างขึ้นมา

## ข้อควรทราบเรื่องการชำระเงินจริง
การแสดง QR/การสร้างรายการชำระยังไม่เท่ากับการเชื่อมต่อธนาคารจริง การยืนยันอัตโนมัติต้องเชื่อม Payment Gateway และทดสอบ webhook signature กับผู้ให้บริการก่อนเปิด `PAYMENT_MODE=live` ส่วนการรับเงินสดโดยแอดมิน/พนักงานเป็นการบันทึกการรับเงินจริงด้วยคน ไม่ได้โอนหรือหักเงินผ่านธนาคาร

## ตรวจสอบก่อนใช้งาน
รัน `npm run check` เพื่อตรวจ syntax ของไฟล์ JavaScript จากนั้น `npm start` เพื่อเริ่มระบบ
